# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (v1.2)
## Telegram-бот для генерации презентаций PowerPoint

---

## 0. Реквизиты проекта

| Поле | Описание |
|---|---|
| **Название** | **Автогенератор презентаций** (PPTGeneratorBot) |
| **Проблема** | Автоматическое создание презентации: пользователь тратит десятки минут на ручную компоновку слайдов, подбор тезисов и оформление. Нужен сервис, который собирает черновую презентацию за минуты по одной только теме. |
| **Пользователи** | Методисты, студенты, школьники |
| **Основная функция** | Сервис запрашивает тему презентации, спрашивает количество слайдов, формирует структуру презентации, генерирует контент, запрашивает фотографии для презентации у пользователя, собирает презентацию, отправляет готовый файл пользователю |
| **Формат результата** | Файл с презентацией (`.pptx`) и, при необходимости, файл с текстом (`.txt` / `.md` со всеми тезисами) |
| **Минимальный функционал (v1)** | Команда `/start`; кнопки подтверждения действий бота или отказа для изменения (бот переспрашивает, что именно нужно изменить/дополнить); приём фотографий от пользователя; сбор всех данных в презентацию; отправка результата пользователю |
| **Технологии** | Python 3.11+, aiogram 3.x (Telegram), httpx (async HTTP), Ollama Cloud API (модель `minimax-m3:cloud`), python-pptx (сборка .pptx), aiosqlite (хранилище), pydantic-settings (конфиг), loguru (логирование) |
| **Критерии хорошего результата** | Понятная идея и описание задачи; рабочий локальный запуск; пользовательский сценарий; минимальный интерфейс; демонстрируемый результат; структура файлов проекта; README с инструкцией запуска |

## 2. Функциональные требования

### 2.1 Команды
- `/start` — приветствие + инструкция
- `/help` — справка
- `/cancel` — сброс состояния

### 2.2 Сценарий

1. `/start` → FSM `WAITING_TOPIC`
2. Текст с темой (≤ 500 симв.) → `WAITING_SLIDES_COUNT`
3. Число слайдов (3–25) или «по умолчанию» (8–10)
4. `WAITING_PHOTOS` — пользователь присылает фото:
   - одиночно (с накопительным счётчиком «1/7, 2/7…»)
   - альбомом (1–10 фото в одном сообщении, обрабатывается по `media_group_id`)
   - «без фото» / «пропустить» — переход к шагу 5
   - **>7 фото** → ошибка, возврат в `WAITING_PHOTOS`
5. Проверка дневного лимита (≤ 2/день/user_id по Москве)
6. Запрос к Ollama Cloud (модель `minimax-m3:cloud`) с темой и числом слайдов
7. Парсинг JSON, retry до 2 раз при невалидном ответе
8. Сборка `.pptx` через `python-pptx` на брендированном Ч/Б шаблоне
9. Отправка файла пользователю
10. Инкремент счётчика, сброс FSM

### 2.3 Обязательные блоки
- F1. Валидация ввода
- F2. Rate limiting (2/день/user_id, TZ Europe/Moscow)
- F3. Поддержка альбомов (`media_group_id`) и одиночных фото
- F4. Хранилище FSM + счётчиков в SQLite
- F5. Retry/обработка ошибок Ollama
- F6. Очистка `/tmp` после отправки
- F7. Логирование

## 4. Архитектура

```
Telegram User ─► aiogram bot ─► Ollama Cloud (minimax-m3:cloud)
                       │
                       ├──► SQLite (FSM, счётчики, TZ)
                       └──► python-pptx (сборка .pptx)
```

### Модули
- `bot.py` — точка входа
- `handlers/` — `start`, `topic`, `photos`
- `services/` — `ollama_client`, `pptx_builder`, `limits`
- `storage/` — `sqlite.py` (aiosqlite)
- `templates/` — `minimal_bw.pptx` (Ч/Б шаблон)
- `utils/` — `logging`, `validators`
- `config.py` — pydantic-settings

### FSM
```
START → WAITING_TOPIC → WAITING_SLIDES_COUNT → WAITING_PHOTOS
                                                     │
                                                     ├─► PHOTO_LIMIT_ERROR → WAITING_PHOTOS
                                                     ├─► GENERATING
                                                     │     ├─► SENDING → DONE
                                                     │     └─► ERROR → DONE
                                                     └─► /cancel → START
```

## 6. Промпт и формат ответа

### System
```
Ты — ассистент, который генерирует структуру презентации.
Ответ — СТРОГО валидный JSON без markdown-обёрток и пояснений.
Язык ответа: русский.
```

### User
```
Тема: «{TOPIC}».
Слайдов: {N}.
Сгенерируй структуру в формате:
{"slides":[{"title":"...","bullets":["...","..."]}]}
- 2–5 тезисов на слайде, каждый ≤ 120 символов.
- Никакого текста вне JSON.
```

### Маппинг фото
- `len == 0` — слайды только текст
- `len == N` — фото `i` → слайд `i`
- `len < N` — распределение по слайдам 2..N
- `len > 7` — ошибка

### Шаблон `.pptx`
- 16:9
- Фон: белый
- Заголовки: чёрные, 28 pt, bold
- Буллеты: чёрные, 20 pt
- Акценты: красная полоса под заголовком (3 pt)
- Изображения: центрированы, `max_width = slide_width * 0.8`

## 7. Обработка ошибок

| Сценарий | Действие |
|---|---|
| Ollama timeout (60 с) | retry 1 раз → «сервис недоступен» |
| Невалидный JSON | retry 1 раз с ужесточённым промптом |
| Нет поля `slides` | ошибка валидации |
| Неверное число слайдов | обрезка/дополнение + warn в лог |
| Файл > 50 МБ | запрет, сообщение пользователю |
| Превышен лимит | «Вы использовали 2/2 генераций сегодня» |
| Crash при сборке | cleanup, «Ошибка генерации» |
